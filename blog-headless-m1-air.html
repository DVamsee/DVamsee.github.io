What changed from the original guide

  • n8n is no longer fully public. The original funnels the whole editor to the internet. Here only /webhook paths go public on port 8443; the editor stays private on your tailnet over HTTPS.
  • n8n login works. Plain http://100.x.y.z:5678 trips n8n's secure-cookie check. Tailscale Serve gives it real HTTPS.
  • Tailscale survives reboots before login by running as a system daemon, and node-key expiry is disabled so it doesn't drop off after ~180 days.
  • FileVault is a choice, not a default-off. The trade-off is spelled out in step 1.4.
  • Ollama uses the GPU (Metal), not the Neural Engine, and macOS does not pin containers to performance cores. The architecture diagram is redrawn accordingly.
  • Added: Homebrew PATH setup, SSH key-only login, update control, a RAM reality check, and a reboot test you run while sitting next to the machine.
00

Reality check

Five minutes here saves you from planning a stack the hardware can't hold.

Check RAM and macOS version Added

Terminal
sysctl -n hw.memsize | awk '{print $1/1073741824 " GB RAM"}'
sw_vers -productVersion
8 GB machine: n8n + Postgres + a 3B Ollama model + a headless browser is roughly the ceiling. "Dozens of containers" is not realistic. On 16 GB you have real headroom.

Pick a spot and a network Added

  • Hard, open surface or a vertical stand. The Air is fanless and sheds heat through the chassis; on fabric it throttles.
  • A USB-C Ethernet adapter is worth it. Wi-Fi drops are the most common reason a headless Mac "disappears".
  • Set a DHCP reservation for it on your router so its LAN IP never changes.
01

macOS prep

Do all of this with the lid open and a keyboard attached. Close the lid only after phase 4 passes.

Name the machine Added

This becomes its Tailscale name too, so pick it now.

Terminal
sudo scutil --set ComputerName {{HOST}}
sudo scutil --set HostName {{HOST}}
sudo scutil --set LocalHostName {{HOST}}

Turn on SSH, Screen Sharing and accessories

  • System Settings → General → Sharing: turn on Remote Login and Screen Sharing.
  • System Settings → Privacy & Security → Allow accessories to connect: set to Always, so USB devices (like the Ethernet adapter) work with the lid shut.

Stop it from sleeping with the lid closed

Terminal
sudo pmset -a sleep 0
sudo pmset -a disksleep 0
sudo pmset -a disablesleep 1
sudo pmset -a tcpkeepalive 1
sudo pmset -a displaysleep 5   # screen can sleep; the system won't

pmset -g   # verify: SleepDisabled 1, sleep 0

Also: System Settings → Battery → Options → turn on Prevent automatic sleeping on power adapter when the display is off.

To undo later: sudo pmset -a disablesleep 0

Decide how it recovers from a reboot Fixed

OrbStack, PM2 and AlDente only start once a user is logged in. FileVault blocks auto-login. So you are choosing between unattended recovery and disk encryption:

A · Physically secure locationFileVault off, auto-login on. Fully unattended. Anyone who picks up the laptop has your data.
B · Laptop could walk awayKeep FileVault on. Planned reboots use sudo fdesetup authrestart. Unplanned reboots need you at the keyboard.
C · HybridFileVault on, and keep secrets (API keys, n8n credentials) out of plain files. Accept manual recovery.

For option A: Privacy & Security → FileVault → Off (decryption takes a while), then Users & Groups → Automatically log in as → your user.

Option B — planned reboot that skips the FileVault screen once
sudo fdesetup authrestart

Stop surprise update reboots Added

System Settings → General → Software Update → Automatic updates (ⓘ): turn off Install macOS updates. Keep "Download new updates" on. Patch on your schedule:

Monthly, while you're nearby
softwareupdate -l
sudo softwareupdate -ia --restart

Cap the battery at 80%

Sitting at 100% on a charger for months accelerates wear and can lead to swelling. Two options:

GUI app — needs a logged-in session; enable "Launch at login"
brew install --cask aldente
Headless daemon — runs before login
brew install batt
sudo brew services start batt
batt limit 80

Run Homebrew setup (step 2.1) first if brew isn't installed yet.

02

Remote access

Tailscale gives the Mac a stable private address reachable from anywhere, without opening router ports.

Install Homebrew and put it on your PATH Fixed

On Apple Silicon, Homebrew lives in /opt/homebrew, which isn't on PATH by default. The original guide skips this, so brew fails in new shells and over SSH.

Terminal
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
brew --version

Install Tailscale as a system daemon Fixed

The GUI app only connects after someone logs in. The daemon starts at boot, so the Mac is reachable even sitting at the login window.

Terminal
brew install tailscale
sudo brew services start tailscale
sudo tailscale up --hostname={{HOST}}
# open the printed URL to authorise the machine

tailscale ip -4

Then in the Tailscale admin console:

  • Machines → {{HOST}} → ⋯ → Disable key expiry. Otherwise the server drops off your tailnet when its key expires.
  • DNS: turn on MagicDNS and HTTPS Certificates (needed for steps 3.4 and 3.5).

Switch SSH to key-only login Added

On your client laptop:

Client machine
ssh-keygen -t ed25519 -C "laptop-to-{{HOST}}"
ssh-copy-id {{USER}}@{{HOST}}

cat >> ~/.ssh/config <<'EOF'
Host {{HOST}}
  HostName {{HOST}}
  User {{USER}}
  ServerAliveInterval 30
EOF

ssh {{HOST}}

Once key login works, on the server:

Server
sudo tee /etc/ssh/sshd_config.d/100-keys-only.conf <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
sudo launchctl kickstart -k system/com.openssh.sshd
Keep your current SSH session open and test a new connection before closing it. If the new one fails, you can still revert.

VS Code / Cursor: install Remote-SSH, then connect to host {{HOST}} — it reads the config above.

Remote desktop at a usable resolution

Server
brew install --cask betterdisplay

In BetterDisplay, create a virtual screen (e.g. 1920×1080 HiDPI) and enable "Launch at login". Connect from another Mac with vnc://{{HOST}} in Finder → Go → Connect to Server.

03

Automation stack

Containers via OrbStack, workflows in n8n, scripts under PM2, local models from Ollama.

Install OrbStack and make it start at login

Server
brew install --cask orbstack
open -a OrbStack
docker info | head -5

In OrbStack Settings, turn on Start at login. Containers with --restart unless-stopped come back when OrbStack does.

Run Ollama as a background service Fixed

Server
brew install ollama
brew services start ollama
ollama pull llama3.2:3b
curl -s http://127.0.0.1:11434/api/tags | head -c 200

Ollama runs on the GPU through Metal; the Neural Engine sits idle. Stick to 3B-class models on 8 GB, up to ~8B quantised on 16 GB. Containers reach it at http://host.docker.internal:11434.

Run n8n bound to localhost only Fixed

Binding to 127.0.0.1 keeps it off your LAN. Tailscale will be the only way in.

Server
docker volume create n8n_data

docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 127.0.0.1:5678:5678 \
  -e GENERIC_TIMEZONE="{{TZ}}" \
  -e TZ="{{TZ}}" \
  -e N8N_EDITOR_BASE_URL="https://{{HOST}}.{{TAILNET}}/" \
  -e WEBHOOK_URL="https://{{HOST}}.{{TAILNET}}:8443/" \
  -e N8N_PROXY_HOPS=1 \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

In n8n, add an Ollama credential with base URL http://host.docker.internal:11434.

Serve the n8n editor privately over HTTPS Added

Server
sudo tailscale serve --bg 5678

Open https://{{HOST}}.{{TAILNET}} from any device on your tailnet. Nobody outside it can reach this.

Expose only webhooks to the internet Security fix

The original tailscale funnel --bg 5678 puts the whole n8n editor — login page included — on the public internet. n8n has shipped serious security fixes; don't hand attackers the editor.

First allow Funnel for this machine in the admin console (Access controls → nodeAttrs → funnel). Then publish just the webhook paths on port 8443:

Server
sudo tailscale funnel --bg --https=8443 \
  --set-path=/webhook http://127.0.0.1:5678/webhook

# only while building workflows (n8n "test" URLs):
sudo tailscale funnel --bg --https=8443 \
  --set-path=/webhook-test http://127.0.0.1:5678/webhook-test

tailscale funnel status

Public webhook URLs look like https://{{HOST}}.{{TAILNET}}:8443/webhook/…. Add header auth on every public Webhook node.

Keep native scripts alive with PM2

Server
brew install node
npm install -g pm2

cd ~/bots/my-bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
pm2 start main.py --name automation-bot --interpreter ./.venv/bin/python

pm2 save
pm2 startup   # run the sudo command it prints

Point --interpreter at the venv's Python. A bare python3 won't see your packages after a reboot.

04

Verify before you walk away

Run this with the machine in front of you. If anything fails here, it would have failed at 2 a.m. too.

Reboot test with the lid closed Added

Server
sudo reboot   # or: sudo fdesetup authrestart  (FileVault on)

Close the lid. After ~2 minutes, from another device:

Client machine
tailscale ping {{HOST}}
ssh {{HOST}} 'pmset -g | grep -i sleep; docker ps --format "{{.Names}}: {{.Status}}"; pm2 status'
curl -sI https://{{HOST}}.{{TAILNET}} | head -1
curl -sI https://{{HOST}}.{{TAILNET}}:8443/webhook/healthcheck | head -1
Pass = ping replies, SSH works, n8n shows "Up", PM2 lists your bot as online, and both HTTPS checks return a status line. Then leave it closed.
